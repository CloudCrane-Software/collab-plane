# ONBOARD-PROMPT · 新项目接入提示词（owner 复制给新项目的 agent 用）

> 使用场景：某项目已完成自己的开发计划+测试计划（按五强/五弱多模型同流程产出，结构与既有项目一致），owner 把下面这段话发给该项目的 agent，它执行完即自动纳入本机协作平面管理（共享 cron 立即可接它的单）。

---

（以下为提示词正文，直接复制）

你是项目接入 agent。你的项目要加入本机多项目协作平面。工作目录 `D:\workspace\local-plane`。**只做接入，不做开发**。严格按序执行：

1. **上车读规则**：读 `D:\workspace\local-plane\README.md` → `PROTOCOL.md` → `REGISTRY.md`（看清其他项目的行与"接单注意"，你不得触碰它们）。
2. **前置自检**（任一不满足就停止并报告 owner，不要硬接入）：
   - 你的开发计划与测试计划文件已存在且定稿（含多模型思考轨迹留痕）；
   - 测试计划区分可见/holdout，且 holdout 已（或可以随接入动作）放到**仓外/工作区外保密位置**；
   - 你的项目工作区路径不含其他项目的封存区（若含，登记时注明禁触边界）。
3. **建命名空间**：`D:\workspace\local-plane\projects\<你的项目id>\`（id 用小写连字符，简短；目录结构照抄 projects\plane\ 的形态）：
   - `CONTEXT.md`：一段自包含项目说明书（目标/工作区绝对路径/计划与测试文件路径/git 仓与 HEAD/holdout 位置与禁读声明/硬约束清单/接单注意）。写作标准：没见过你项目的 worker agent 读完即可干活。
   - `EXPECTED-STATE.md`：从你的开发计划提炼的多级期望状态（愿景层可省，里程碑层+当前迭代必须）。
   - `CURRENT-STATE.md`：接入时点现状快照（单行单 id、状态词后接冒号）。
   - `BOARD.md`：任务索引表（初始为你从计划首批工作项翻译的种子任务）。
   - `tasks/backlog/`：种子任务卡 2-4 张，**严格按 PROTOCOL §1 frontmatter 格式**，id 用你项目的两三字母前缀（如 xx-0001，不得与既有项目冲突）；每张卡的 context 必须冷上下文自包含（指向你计划文件的具体章节+路径），acceptance 指向你的测试计划对应组（holdout 路径只写"测试计划 §holdout"，不写绝对路径）。
   - `journal/<今日>-onboard.md`：接入记录。
4. **登记**：在 `REGISTRY.md` 表末追加你的一行（各列照抄表头说明，状态=active）。
5. **升级项移交**：你的计划里所有待 owner 拍板事项，逐条转登 `ESCALATION-MENU.md` §二 待裁表（编 ESC-xxx 续号，选项带推荐，提出人写"<项目id> 接入"）。
6. **收尾**：不动其他项目的任何文件；不建 cron（共享 cron 自动覆盖你）；你的最终回复 = 项目id + 种子任务数 + 升级项数 + 一句话状态。

红线：密钥零落盘；不读任何其他项目的 tests/holdout 与任务上下文；不改 REGISTRY 里他人的行；发现前置不满足宁可终止也不凑合。
